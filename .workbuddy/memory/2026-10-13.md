# 2026-10-13（下午）· 范式重构：从产生式规则到时序约束

## 动因
用户明确要求**不要做成 Drools / EasyRules**：`when P then {...}` + 几个 `var` 只是换层皮的 LHS→RHS。
产生式规则在交易所监管场景水土不服的根因——① 状态与计算割裂（`ctx.disclosure.days_overdue` 要微服务外部算好）；
② 时间不是一等公民（只是 `timestamp` 字段）；③ 校验维度浅（无法回答"跨时间维度状态转移是否完备"、
"时序事件是否因果死锁"）。要求 AST 围绕 **4 个一阶核心概念**抽象，执行层下沉到环形缓冲区 / 扁平状态机 / 原生字节码，
为后期 Z3 完备性检验与 LLVM/WASM 编译铺路。

## 四类一阶公民（新 AST）
| # | 概念 | 节点 |
|---|------|------|
| 1a | Entity | `EntityDecl`（`key`/`states`/`initial`/`terminal`）+ `TransitionDecl`（`from/to/on/emit`） |
| 1b | Metric（动态派生信号流） | `MetricDecl` + `MetricBody::{Scalar{expr,guard}, StreamFold{stream,init,acc,item,body}, StreamAgg{stream,kind}}` |
| 2 | Stream & Event | `StreamDecl{source: Event(T)｜Ref(name), ops}` + `StreamOp::{Filter,Map,Window,Fold,Aggregate,Join,CoGroup,Distinct,Union}` + `Lambda{params,body}` |
| 3 | Temporal Invariant (MTL) | `SpecDecl{entity_name,entity_var,given,invariant,violation}` + `TemporalExpr::{Predicate,Always,Historically,Eventually,Until,Since,Within,Implies,And,Or,Not,StreamQuant}` |
| 4 | StateMachine & Violation | `ViolationHandler{severity,guard,transition,message}` |

`SpecFile { entities, streams, metrics, specs }` 取代旧的 `{entities,streams,signals,vars,contracts}`；
删除 `ContractDecl`/`VarDecl`/`SignalDecl` 与 `TemporalExpr::WithinOp`。

  `path_call_expr`（`Trades.count()`）。

## 三条设计铁律（FrozenLatch / PEP）
1. **单调**：冻结时刻只增不减（`fetch_max`），杜绝"续期把租约改短"的竞态。
2. **逻辑删除保键槽**：`clear_expired` 只把值置 0、不搬移键，保证单次 load 的**确定延迟**（无 rehash 抖动）。
3. **未知键 fail-open**：位图里查不到 ≠ 冻结；真正的拦截权威仍在 PDP。

  ```` ```text ````，并把同逻辑写成真实 `#[test]`。
- Python `urllib` 在 Windows 会读**注册表代理**，本地回环请求必须
  `urllib.request.build_opener(urllib.request.ProxyHandler({}))`，否则 502。
- 用 Bash 工具起后台服务必须 `run_in_background=true`，否则子进程随工具调用结束被杀。
- `serde_json` 里 `json!(20)`（整数）与 `json!(20.0)`（浮点）**不相等**，断言数值时统一用 `json!(x.0)`。
